EXT · 01

AMM natif

The protocol-integrated DEX — XLS-30

No smart contract to deploy: the AMM is une primitive du ledger. N'importe quelle paire de tokens (XRP/IOU ou IOU/IOU) peut avoir son pool.

Les Payment exploitent automatiquement l'AMM dans leur pathfinding — un swap est une transaction standard.

XLS-30 LP tokens Auto-bridging No SC risk
EXT · 02

Real-World Assets

Tokenisation institutionnelle — MPT, DID

Avec Multi-Purpose Tokens (MPT), an issuer can represent bonds, funds, real estate, carbon credits avec metadata, permissions et hooks de compliance natifs.

Coupled with DID et Credentials XLS-70 for on-chain KYC — fits regulated institutions.

MPT DID / Credentials Compliance Ondo · Archax
EXT · 03

EVM Sidechain

Smart contracts complets — bridge XRP

Pour des cas d'usage qui exigent du code Turing-complet (lending, perps, gaming, complex contracts), a dedicated EVM sidechain exists and bridges XRP via wXRP.

Solidity developers deploy their existing contracts; fees are paid in XRP. MetaMask, Hardhat, Foundry compatible.

EVM compatible Solidity Axelar bridge wXRP

Quand utiliser quoi ?

Decision matrix · L1 vs extensions
Besoin Couche What it brings Trade-offs
Paiement, transfert, escrow simple L1 natif 3–5s finality, fees in drops, Payment / Escrow / Check primitives directly in the ledger. No custom logic beyond what the protocol offers.
NFT, collectibles, royalties L1 · XLS-20 Mint, transfer, sell offers, royalties on-chain natifs. Pas besoin de standard ERC. Off-chain metadata (IPFS / URI) — as elsewhere.
Swap de tokens, market making AMM XLS-30 Native pool, no smart contract to audit, integrated into payment pathfinding. Constant-product model only — no stableswap or concentrated liquidity.
Tokeniser obligations, fonds, immo MPT + DID Fungible tokens with rich metadata, per-issuer permissions, KYC integration via credentials. Recent adoption — institutional ecosystem still building.
Lending complexe, perps, gaming Sidechain EVM Solidity / standard EVM, reusable Ethereum ecosystem, secure bridge. Trust assumption on the bridge; finality & security distinct from L1.
