01

L'utilisateur

The starting point. Their sovereignty depends on a single factor: who holds the private key. That's the boundary between self-custody and delegated custody.

02

L'application

Classic web app or dApp. It orchestrates UX, reads the chain via a indexer or a node, and proposes actions to sign — but never signs.

03

Le wallet

Key and asset container: XRP, IOUs (trustlines), NFTs (XLS-20), MPT, parts d'AMM. Self-custody (Xaman, Ledger) ou custodial (CEX).

04

Le ledger

The XRPL network: a graph of validators (UNL) that closes a new ledger every 3–5 seconds. Deterministic finality, no extended mempool.

Reads & writes to the chain

Two paths, two trust requirements
→ READ · gratuit, sans signature
  1. The app queries a rippled node via JSON-RPC or WebSocket
  2. Methods: account_info, account_lines, account_nfts, book_offers…
  3. Indexers (XRPL Data API, Bithomp) for historical / aggregated queries
  4. Real-time subscriptions: stream of new ledgers, transactions of an account
  5. No cost, no risk — but depends on trust in the node
→ WRITE · signed, paid, final
  1. L'app construit la transaction (Payment, OfferCreate, NFTokenMint…)
  2. The wallet signs it locally with the private key
  3. Submission to the network via submit on a node
  4. Consensus RPCA : ~80% des validateurs UNL doivent s'accorder
  5. Inclusion in a validated ledger → state mutated, fees burned (XRP drops)

La question du custody

Who holds what · responsibility matrix
Model Private keys Implications Exemples sur XRPL
Self-custody utilisateur Full sovereignty. The user signs each transaction themselves. Risk: lost seed = lost access. No third party to default. Xaman, Crossmark, Ledger, GemWallet
Custodial plateforme The user has a balance recorded in a database, not their own XRPL account. The platform signs on their behalf. Counterparty risk (insolvency, freeze, hack). Binance, Bitstamp, Kraken, Bitvavo
Hybride / MPC shared The key is fragmented (multi-party computation, native XRPL multisig). No single party can sign. Trade-off between sovereignty and operational security. Fireblocks, multisig SignerList XRPL
