01

L'utilisateur

Le point de départ. Sa souveraineté dépend d'un seul facteur : qui détient la clé privée. C'est la frontière entre self-custody et custody déléguée.

02

L'application

Web app classique ou dApp. Elle orchestre l'UX, lit la chaîne via un indexer ou un node, et propose des actions à signer — mais ne signe jamais.

03

Le wallet

Conteneur de clés et d'assets : XRP, IOUs (trustlines), NFTs (XLS-20), MPT, parts d'AMM. Self-custody (Xaman, Ledger) ou custodial (CEX).

04

Le ledger

Le réseau XRPL : un graphe de validateurs (UNL) qui ferme un nouveau ledger toutes les 3–5 secondes. État final, pas de mempool prolongé.

Lectures & écritures sur la chaîne

Deux chemins, deux exigences de confiance
→ READ · gratuit, sans signature
  1. L'app interroge un node rippled via JSON-RPC ou WebSocket
  2. Méthodes : account_info, account_lines, account_nfts, book_offers…
  3. Indexers (XRPL Data API, Bithomp) pour requêtes historiques / agrégées
  4. Subscriptions temps réel : flux des nouveaux ledgers, transactions d'un compte
  5. Aucun coût, aucun risque — mais dépend de la confiance dans le node
→ WRITE · signée, payante, finale
  1. L'app construit la transaction (Payment, OfferCreate, NFTokenMint…)
  2. Le wallet la signe localement avec la clé privée
  3. Soumission au réseau via submit sur un node
  4. Consensus RPCA : ~80% des validateurs UNL doivent s'accorder
  5. Inclusion dans un ledger validé → état modifié, frais brûlés (drops de XRP)

La question du custody

Qui détient quoi · matrice de responsabilité
Modèle Clés privées Implications Exemples sur XRPL
Self-custody utilisateur Souveraineté totale. L'utilisateur signe lui-même chaque transaction. Risque : perte de seed = perte d'accès. Pas de tiers à faire défaut. Xaman, Crossmark, Ledger, GemWallet
Custodial plateforme L'utilisateur a un solde inscrit dans une base de données, pas un compte XRPL à lui. La plateforme signe en son nom. Risque de contrepartie (faillite, gel, hack). Binance, Bitstamp, Kraken, Bitvavo
Hybride / MPC partagées La clé est fragmentée (multi-party computation, multisig XRPL natif). Aucun acteur seul ne peut signer. Compromis souveraineté ↔ sécurité opérationnelle. Fireblocks, multisig SignerList XRPL
